# ansible-role-authentik

Deploys [authentik](https://goauthentik.io) (self-hosted SSO / identity
provider) via Docker Compose, optionally behind nginx/TLS.

## Layout

```
.
├── ansible.cfg
├── requirements.yml
├── playbooks/site.yml          # play applying the role
├── inventory/
│   ├── hosts.yml                 # authentik_servers group
│   └── group_vars/
│       ├── all/                  # domain, vm_fqdn
│       └── authentik_servers/    # role vars (version, dir, public fqdn)
└── roles/
    └── authentik/                 # the role itself
```

## What it deploys

A `docker-compose.yml` matching authentik's own recommended stack:

- `postgresql` — the only datastore authentik needs as of the 2026.x
  releases (Redis is no longer required upstream).
- `server` — the web UI / API, listening on `9000` (HTTP) / `9443` (HTTPS)
  bound to `authentik_http_bind_address` (default `127.0.0.1`).
- `worker` — background tasks and outpost management. Runs as `root` with
  `/var/run/docker.sock` mounted so it can manage outpost containers
  automatically; swap that for a Docker Socket Proxy if the broad socket
  mount is unacceptable for your environment.

Runtime secrets (`PG_PASS`, `AUTHENTIK_SECRET_KEY`) are generated once on
first run and written to `/opt/authentik/.env` (root-only, `0600`). They are
never regenerated by a later run — doing so would orphan the database and
invalidate every session — and never round-trip through Ansible.

## Variables

See `roles/authentik/defaults/main.yml` for the full list. Notable ones:

| Variable | Default | Purpose |
|---|---|---|
| `authentik_version` | `2026.8.1` | Image tag; pinned rather than tracking `latest`. |
| `authentik_dir` | `/opt/authentik` | Compose project + data directory. |
| `authentik_http_bind_address` | `127.0.0.1` | Host bind address for the server ports. |
| `authentik_manage_nginx` | `false` | Set `true` to have the role install/configure an nginx TLS vhost. |
| `authentik_extra_env` | `{}` | Extra `key: value` pairs merged into `.env` (e.g. SMTP settings). |

Set `authentik_manage_nginx: true` and populate `acme_cert_fullchain_file` /
`acme_cert_key_file` (or point them at your own cert/key) to have the role
terminate TLS locally.

## Dependencies not vendored here

`playbooks/site.yml` also runs `common`, `docker`, and `acme_cert` —
sibling roles from the `proxmox-ansible-roles` monorepo that were not
copied into this directory. Supply them yourself (e.g. via `roles_path` or
`ansible-galaxy role install -p roles/`) before running the playbook, or
strip them and pre-bake the equivalent: base packages, Docker Engine, and
(if `authentik_manage_nginx: true`) a TLS cert at the paths
`roles/authentik` expects.

## First run

After the play completes, browse to `https://<authentik_public_fqdn>` (or
`http://<host>:9000` if not fronting with nginx) and follow the initial
setup flow at `/if/flow/initial-setup/` to set the `akadmin` password.
